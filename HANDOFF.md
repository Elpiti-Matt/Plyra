## Принятые решения и реализованное поведение

1. **Типы → Листы:** сверху словарь тегов, затем типы листов, затем реальные листы. Везде доступно добавление. У листа один тип и несколько тегов. Списков разрешённых/запрещённых типов узлов и связей нет.
2. **Узлы:** типы Plyra, Flowchart, Obsidian Canvas, базовые BPMN и пользовательские определения; декоративных пиктограмм нет. Форма отражает нотацию. Классификация листа не ограничивает его содержимое.
3. **Связи:** текстовые типы отношений. Сплошные линии внутри листа, пунктир между листами, золотые линии между появлениями одного ID. Тип отношения не управляет штрихом линии. В All-to-1 грамматика отражает исходные членства.
4. **Атрибуты:** словарь определений с названием и типом данных; значения добавляются к узлам и общие для всех появлений. Типы: текст, число, да/нет, дата, URL, список вариантов. Плюс на узле открывает текст и атрибуты; правки входят в историю.
5. **Показ:** независимые **Выбрать все / Выключить все** для типов узлов и связей, включая пользовательские. Снятие отметок приглушает объекты на месте, не удаляя данные, линии, координаты или счётчики. **Показать все типы** сбрасывает обе группы.
6. **Листы:** редактор одного листа и **Обзор листов / Helicopter view**. «− Все листы» справа сверху выходит в обзор; «+» в углу листа открывает его редактор. Термин для объекта — «лист»; Canvas остаётся названием внешнего формата или техническим именем компонента.
7. **Обзор:** свободное расположение всех листов с настоящими узлами, локальными/межлистовыми связями и общими ID. Листы перемещаются за заголовки, узлы — внутри своего листа. Перенос узла не меняет членства; новое появление добавляется в свойствах через «+ ещё лист…».
8. **Только для выделенного листа:** фильтр обзора оставляет межлистовые отношения выбранного листа и золотые линии ко всем другим появлениям общего ID. Фокус меняется нажатием/фокусом заголовка. **Между листами** и **Один ID** работают независимо. Все листы и локальные связи остаются видны.
9. **Разворот:** отдельное сравнение 2–6 выбранных листов рядом с настройкой пропорций. **Стопка:** «Построчно» / «Узлы и связи», все узлы выбранных листов, тип/тег для группировки и собственная оптимизация. **Оглавление:** обобщённая схема или список.
10. **Все на один лист / All-to-1:** одна редактируемая карточка на сущность, отдельное сохраняемое расположение; текст и атрибуты общие. Исходные листы и членства сохраняются.
11. **ИИ:** встроенный и скачиваемые промпты, примеры и учебные GIF используют Plyra v3. Показаны пять словарей, один тип/теги листа и все шесть типов атрибутов. Plyra не вызывает внешний ИИ; пользователь переносит промпт и проверяет ответ.
12. **Документация:** README RU/EN перечисляют доступные функции, показывают схемы режимов/атрибутов и GIF. FEATURES объясняет действия пользователя. UPDATE-GITHUB подробно описывает первое обновление конкретного репозитория через Desktop, PR и ручной Pages.

## Данные и реализация

Нативный `.plyra` — JSON v3. Словари: `types.nodes`, `edges`, `sheets`, `tags`, `attributes`. Классификация листа — `typeId`, `tags`. `node.attributes` содержит значения по ID определения, `null` — добавленное, но незаданное значение. Legacy v1/v2 читаются; ключи браузерного хранилища сохраняются для совместимости.

`Sheet.overviewPos: {x,y}` хранит положение целого листа независимо от `node.pos[sheetId]`. Первое перемещение заголовка фиксирует все текущие положения листов, чтобы соседи не перескакивали из-за сетки. Перемещение узла меняет только его появление и помечает лист `layout:"manual"`. All-to-1 использует корневое `flatPositions`.

Жесты учитывают масштаб обзора и внутреннего предпросмотра. Один завершённый жест — одно действие отмены. Escape, pointercancel, потеря захвата и начало pinch отменяют незавершённое перемещение. Фон и колесо перемещают обзор; кнопки, Ctrl/⌘ + колесо и два пальца меняют масштаб. Стрелки двигают заголовок/узел с клавиатуры, Shift увеличивает шаг, Enter открывает лист. Камера сохраняется при переходах уровней в сеансе; после перезагрузки обзор вписывается заново.

Основные файлы: `OverviewCanvas.tsx` — вид/жесты/фокус; `overviewLayout.ts` — геометрия; `spreadGraph.ts` — маршруты. В `overviewRoutes` выбранный лист соединяется попарно с каждым другим: простой отбор существующей цепочки `identityRoutes` пропустил бы часть общих появлений. Эти маршруты не создают новых связей графа. `VisibilityDialog.tsx` использует полные словари TypeContext для групповых действий.

`generation.ts` — единый источник AI-промптов/примеров. `npm run ai:docs` проверяет загрузку примеров и записывает `docs/AI-PROMPT.*.txt`, `data/ai-example-*.json`. Тест требует точного совпадения файлов с приложением. Учебные GIF/PNG и встроенный `helpMedia.ts` пересобираются `python3 scripts/build_help_media.py` (Pillow, DejaVu Sans); SVG документации — `python3 scripts/build-doc-diagrams.py` (стандартная библиотека). Это оригинальные схемы, не скриншоты приложения.

## Границы реализации

- draw.io, JSON Canvas и BPMN DI добавляют листы после предпросмотра. Базовые формы, размеры и позиции сохраняются; draw.io/BPMN сохраняют маршруты. Сложные фигуры, маркеры, группы, оформление и подписи могут упрощаться. Изображения, вложения и внешние файлы не загружаются. Прямого импорта Miro нет; универсального 1:1 не обещать.
- BPMN без DI отклоняется. Сплошные внутренние линии меняют визуальные соглашения BPMN/UML; смысл остаётся в типе/подписи. draw.io без семантических метаданных даёт тип «см.», двусторонние стрелки Canvas упрощаются. Предпросмотр сообщает ограничения.
- `.plyra` — формат продолжения работы. draw.io и Canvas — проекции, не сохраняющие обзорную расстановку листов и All-to-1. Совпавшие имена при импорте не объединяют сущности; группы не являются полноценными переносимыми контейнерами.
- Для подробного редактирования текста/атрибутов из обзора открыть лист через «+». Оптимизация листа/разворота меняет нативные позиции и заменяет импортированные маршруты автоматическими; отмена возвращает прежние. Стопка оптимизирует только своё представление, All-to-1 — flatPositions. Автоматической расстановки целых листов в обзоре пока нет; есть вписывание.
- Фильтры, камера и раскладка стопки — состояние представления. Сохраняются данные и координаты листов/узлов/All-to-1. Лимиты: 100 листов, 1 000 сущностей, 5 000 связей, 200 определений на словарь, 10 МиБ входных/распакованных данных.
