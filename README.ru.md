# Plyra

Карта знаний на связанных листах. У сущности один ID, общие название, текст и атрибуты; её появления на листах имеют собственные координаты и оформление.

## Открыть

Скачайте `demo/index.html` и откройте в браузере: это автономный HTML без внешних ресурсов. Для продолжения работы сохраняйте карту через **Проект → Скачать .plyra**. Сайт обновляется отдельным запуском Pages и может отставать от версии исходников.

## Доступные возможности

| Возможность | Что можно делать |
| --- | --- |
| **Листы** | Редактировать один лист, двигать узлы, раскрывать текст и атрибуты плюсом |
| **Обзор листов / Helicopter view** | Через «− Все листы» увидеть все листы; двигать их за заголовки, масштабировать обзор, вернуться в редактор через «+» |
| **Связи выделенного листа** | В обзоре включить «Только для выделенного листа» и нажать заголовок. Видны его межлистовые связи и золотые линии ко всем появлениям общего ID |
| **Разворот** | Сравнивать 2–6 выбранных листов рядом с настройкой пропорций |
| **Стопка** | Переключать «Построчно» / «Узлы и связи», показывать все узлы выбранных листов, группировать по типу/тегу и оптимизировать вид |
| **Все на один лист / All-to-1** | Показать каждую сущность один раз, редактировать её и сохранять отдельное расположение |
| **Оглавление** | Смотреть структуру листов схемой или списком |
| **Типы и теги листов** | Вести словарь тегов, словарь типов и сами листы. У листа один тип и несколько тегов |
| **Типы узлов** | Использовать Plyra, Flowchart, Obsidian Canvas, базовые BPMN и свои определения; форма отражает нотацию |
| **Типы связей** | Задавать текстовые отношения: «зависит от», «наследует от» и другие |
| **Атрибуты** | Создавать определения и добавлять к узлам значения: текст, число, да/нет, дата, URL, вариант из списка |
| **Показ на экране** | Отдельно выбирать или выключать все типы узлов и все типы связей; невыбранные объекты приглушаются на месте |
| **Импорт диаграмм** | Добавлять листы из draw.io, JSON Canvas и BPMN DI после предпросмотра ограничений |
| **Проверка проекта** | Вызвать «Справка → Проверить проект», увидеть замечания к структуре и членствам |
| **Совместимые данные** | Открывать старый JSON и пару nodes.csv / edges.csv, загружать встроенные примеры |
| **Работа с проектом** | Создавать пустую карту, открывать/сохранять .plyra, экспортировать представления, отменять/повторять правки, использовать автосохранение |
| **ИИ и справка** | Скопировать промпт Plyra v3 с атрибутами, скачать пример JSON, читать FAQ на RU/ENG; подключение к внешнему ИИ не требуется |

## Режимы и атрибуты

![Лист, обзор всех листов и отличие от разворота, стопки и All-to-1](docs/images/views-ru.svg)

*Учебная схема режимов, не скриншот интерфейса. Положения листов и узлов независимы. Узел перетаскивается только внутри своего листа; текст и атрибуты общие у всех появлений одного ID.*

![Определение числового атрибута и общие значения на двух листах](docs/images/attributes-ru.svg)

*Учебная схема атрибутов. Сначала определение в «Типы → Атрибуты», затем значение у узла. Значения на картинке вымышленные.*

## Импорт и границы поддержки

`.plyra` открывает целый проект. `.drawio`, `.canvas` и `.bpmn` добавляют листы после предпросмотра. Сохраняются координаты, размеры и базовые формы; draw.io и BPMN также сохраняют точки маршрутов. Импортированные узлы доступны для редактирования и связей между листами.

Сложные фигуры, маркеры, оформление текста и группы могут упрощаться. Изображения, вложения, фоны и содержимое внешних файлов не загружаются. BPMN требует DI. Прямого импорта резервной копии Miro нет. Это не обещание универсального совпадения 1:1 с исходным редактором.

В BPMN/UML штрих линии может обозначать смысл. В Plyra внутренние связи сплошные, а смысл хранится в типе и подписи; результат не является строгой визуальной нотацией. Для дальнейшего редактирования сохраняйте `.plyra`; draw.io и Canvas — переносимые представления.

Лимиты: 10 МиБ на набор входных и распакованных данных, 100 листов, 1 000 сущностей, 5 000 связей, 200 определений на словарь. Фильтры, камера обзора и раскладка стопки — настройки сеанса; координаты листов, узлов и All-to-1 сохраняются в проекте.
