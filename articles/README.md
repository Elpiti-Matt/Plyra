# Редакторский комплект

Здесь две полные рабочие версии: `habr-working-draft.md` и `english-working-draft.md`. Они подготовлены с участием ИИ и не представлены как готовые к копированию публикации.

На 5 сентября 2026 [правила Хабра](https://habr.com/ru/docs/help/rules/) отдельно ограничивают сгенерированные и отредактированные нейросетями тексты, с узким исключением для небольшого дополнения к большой авторской технической статье. [Правила HN](https://news.ycombinator.com/newsguidelines.html) запрещают генерированные и AI-edited комментарии. Поэтому итоговый материал для Хабра и комментарии на HN автору следует написать самостоятельно на основе собственных наблюдений. Этот комплект даёт структуру, исправления и проверенные опорные факты, а не способ обойти правила.

Английская версия — самостоятельное эссе для внешней страницы/блога, на которое можно сослаться при обычном сабмите, если оно соответствует выбранной площадке. HN не является хостингом длинной статьи. Для Show HN нужна ссылка на работающий инструмент и личное участие автора; [официальные требования](https://news.ycombinator.com/showhn.html).

Описания возможностей сверены с rc.4 9 сентября 2026 года. Правила площадок ниже приведены с датой исходной проверки; перед отправкой собственной статьи проверьте их актуальную редакцию.

## Что изменилось в аргументе

| Было | Почему изменено | Теперь |
|---|---|---|
| Карты умирают около 200 узлов | Нет исследования или воспроизводимого опыта во вложениях | Вопрос о размере вида, без универсального порога |
| Снижение пересечений в 50 раз | Нет скрипта, исходных данных и определения метрики; раскладки отличаются | Нет численного заявления о выигрыше |
| 126 из 225 узлов требуют мультичленства | Во вложениях нет описанной доски | Только фактические размеры учебных наборов |
| Ортогональность Харела разрешает мультичленство | Это разные понятия | Идейная аналогия с явным пределом |
| Любой элемент дерева ровно в одном множестве | Вложенность допускает членство в предках | Вложенные или непересекающиеся множества |
| Пересекающиеся листы — полурешётка | Не проверяется замкнутость семейства по пересечениям | Общее семейство пересекающихся видов |

| Любая строгая нотация запрещает гибриды | Обобщение не доказано; расширения возможны | Ограниченный вид не должен обеднять источник |
| Карпаты не предусмотрел виды | В gist явно упоминается canvas | Предложение сохраняемых ограниченных видов и диффа |
| Цена поставщика меняет этикетку | Нет такого прямого следствия | Цена → возможная замена → проверка рецепта и макета |
| Кофе, Flask, Python-скрипты, замер поиска уже в репо | В исходных вложениях этого нет | Кофе и Node CLI добавлены; Flask и таймер не заявлены |
| UI хорошо работает на телефоне | Нет физического теста | Показан открытый статус QA |

## Авторская финальная работа

1. Вернуть личный эпизод с доской, только если он действительно ваш: что пытались найти, кто пользовался, как определили, что доску перестали читать. Числа и «одиннадцать месяцев» не заменяют наблюдение.
2. Провести ручной прогон из `../docs/QA-MANUAL.md` и добавить собственный результат, включая неудобства.
3. Написать окончательный текст самостоятельно. Особенно важны личные решения и то, где прототип оказался неудобнее ожидаемого.
4. Заполнить владельца GitHub через `scripts/configure_repo.py`, проверить реальные ссылки, затем убрать редакторские заметки из собственной публикационной версии.
5. До новых данных не возвращать универсальный порог, выигрыш «50×» и рассказ про реальную платёжную доску.

## Иллюстрации

Скриншоты не создавались: рабочий браузерный предпросмотр недоступен. Не заменять их постановочными изображениями интерфейса. Достаточно шести реальных кадров после ручной проверки:

| Кадр | Где в статье | Что должно быть видно |
|---|---|---|
| 1. Один объект, три листа | После JSON | Смесь «Утро», общий ID, членства и тело |
| 2. Стаб | После объяснения границы | Подпись внешнего узла и целевой лист |
| 3. Типы и видимость | После раздела о нотациях | Тип/теги листа и приглушение фильтром без исключения узлов |
| 4. Разворот | В разделе видов | Два разных листа и существующая связь; без фиктивного drag |
| 5. Обзор листов и стопка | Там же | Обзор «− / +»; выбранный узел в представлении «Узлы и связи» |
| 6. Телефон | В разделе ограничений/QA | «Читать лист» и инспектор на 390 CSS px |

При необходимости показать общий граф рядом с листом добавить подпись: «разные раскладки; это иллюстрация, не контролируемое сравнение». Не публиковать 12 почти одинаковых кадров: они замедляют чтение.

## HN: подача

Обычный сабмит внешнего эссе: использовать его фактический заголовок **A knowledge graph needs more than one view**.

После проверки работающего демо возможный предмет Show HN: **Plyra — offline knowledge graphs with shared nodes across sheets**. Префикс `Show HN:` подходит только для ссылки на инструмент, который можно попробовать, не для эссе или страницы ожидания.

Не подготовлен комментарий для вставки: правила HN требуют человеческой беседы. Опорные вопросы для собственного первого комментария:

- Какая конкретная задача привела вас к нескольким листам?
- Почему данные кофе вымышленные и как работают RU/ENG?
- Чем общий ID отличается от копий карточек?
- Какие проверки выполнены и какие нет?
- Какую проверяемую критику вы хотите получить: навигация, границы, стоимость мультичленства?

На ожидаемые возражения держите факты: число 200 не доказано; statecharts и мультичленство не тождественны; Markdown-вики уже является видом; деревья с перекрёстными ссылками возможны; уменьшение линий не доказывает ускорения работы.

Для Хабра логичны хабы о визуализации данных и разработке интерфейсов; AI — если раздел о вики останется существенным. Не выбирать четыре хаба только ради охвата. Метки: карты знаний, визуализация, графы, интерфейсы, Obsidian, документация.

Рабочие статьи исключены из MIT-лицензии кода. После самостоятельной финальной редакции рекомендуемый вариант для авторских статей — CC BY 4.0, если автор хочет разрешить переводы и перепубликации с указанием авторства. Сейчас права на публикационные тексты не передаются.
