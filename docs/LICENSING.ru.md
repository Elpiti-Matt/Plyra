> Историческая справка об аудите 6 сентября 2026 года. Исходные дата и версия сохранены; статус живого репозитория и рекомендации того аудита не подтверждались заново. Текущая передача и публикация описаны в [PUBLISHING](PUBLISHING.ru.md) и [UPDATE-GITHUB](../UPDATE-GITHUB.ru.md). Лицензия приложения остаётся MIT.

Проверено 6 сентября 2026 года для исходников `0.6.1-rc.1` и установленного дерева зависимостей. Рекомендация: публичный репозиторий `OWNER/plyra`, демо на GitHub Pages, автономный `plyra.html` в Releases и публичный счётчик скачиваний файлов релиза. Apache-2.0 подходит для собственного кода проекта. В текущем комплекте по-прежнему MIT; этим аудитом основная лицензия не изменена.

## Что именно публиковать

- **Репозиторий:** распакованные исходники, `package-lock.json`, документацию, учебные данные, `LICENSE`, `NOTICE.md`, `THIRD_PARTY_NOTICES.txt` и `.github/workflows/`. `node_modules`, `.qa` и `dist` исключены из исходного архива.
- **GitHub Pages:** собранный `dist/index.html`. Это статический сайт, для работы приложения серверная часть не нужна. Workflow `Publish demo to GitHub Pages` уже включён; он запускается вручную после выбора GitHub Actions в Settings → Pages. Адрес проекта будет `https://OWNER.github.io/plyra/`.
- **GitHub Release:** версионированный `plyra.html` и контрольная сумма. Файл можно скачать и открыть без установки и сетевого подключения. Исходный архив GitHub формирует отдельно.

GitHub Pages доступен для публичных репозиториев на GitHub Free. Для текущего открытого демо это подходящий вариант. Если позже появится коммерческий SaaS или интернет-магазин, нужно учитывать ограничения самого хостинга — разрешительная лицензия кода их не отменяет. [Описание Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [условия использования и лимиты](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

Репозиторий, Pages и релиз пока не опубликованы; `OWNER` — заполнитель. Процедура есть в [инструкции публикации](PUBLISHING.ru.md). Визуальная проверка в браузере и на физических телефонах ещё не завершена, поэтому текущий статус — release candidate.

## Что считать

| Метрика | Реализация | Что она означает |
|---|---|---|
| Скачивания файлов релиза | GitHub `download_count`, бейдж Shields в README | Скачивания assets, включая повторные. Это не число пользователей |
| Посещения страницы демо | Отдельная веб-аналитика на опубликованной странице | Загрузки страницы по правилам выбранного сервиса; не локальное использование |
| Посещения и клоны репозитория | GitHub Insights → Traffic | Статистика репозитория за последние 14 дней; не посещения Pages |
| Открытия скачанного HTML | В текущем приложении не измеряются | Автономный файл не передаёт телеметрию |

В комплекте `scripts/configure_repo.py OWNER` заполняет ссылки и добавляет бейдж в README, а `python scripts/github_stats.py OWNER/plyra` получает сводку через публичный API. Текущий бейдж и итог скрипта считают **все assets всех релизов**, включая ZIP и checksum, если их прикрепить. Для метрики именно приложения нужно отбирать `plyra.html` или оставить его единственным загружаемым asset. Сумма по всем файлам должна так и называться.

Счётчик на самой странице возможен двумя способами: отдельная посадочная страница с аналитикой (например, GoatCounter), либо число скачиваний, подставляемое при сборке. Второй вариант не требует запросов аналитики из браузера, но обновляется только при новой сборке. Текущая политика CSP автономного HTML запрещает внешние изображения и соединения: просто вставить в него удалённый счётчик или скрипт без изменения политики не получится. Ни один из этих вариантов в приложение не добавлен.

При включении веб-аналитики нужно описать её фактический сбор данных. Даже без неё хостинг Pages получает запрос страницы и ведёт журналы безопасности; данные редактируемого графа приложение не отправляет.

Источники: [GitHub Release assets API](https://docs.github.com/en/rest/releases/assets), [Shields](https://shields.io/badges/git-hub-downloads-all-assets-all-releases), [GitHub Traffic](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository), [GoatCounter](https://www.goatcounter.com/).

## Совместимость с Apache-2.0

**Для собственного кода Plyra — да.** Apache-2.0 допускает использование, изменение и распространение, в том числе коммерческое, и содержит явный патентный грант от участников в определённых лицензией пределах. Обязательной публикации всего производного приложения нет. Грант не означает защиту от любых патентов третьих лиц; права на товарные знаки отдельно не предоставляются. [Текст Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0), [FAQ Apache](https://www.apache.org/foundation/license-faq).

MIT-библиотеки сохраняют свои MIT-лицензии и copyright: их уведомления нужно распространять вместе с Plyra, в том числе внутри автономного HTML. Основная лицензия приложения не заменяет лицензии зависимостей. Для текущих MIT-компонентов Apache-2.0 не создаёт конфликта при таком сохранении условий.

**MPL-2.0 у компилятора не переводит его результат автоматически на MPL.** Здесь Lightning CSS служит сборочным инструментом: библиотека и её исходники в HTML не встроены. Если отдельно распространять Lightning CSS или изменённые MPL-файлы, нужно выполнять условия MPL для этих компонентов, включая доступность соответствующих исходников. При объединении кода MPL с другим кодом её требования ограничены покрываемыми файлами. [Mozilla MPL FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/).

**CC-BY-4.0 у caniuse-lite относится к базе данных.** База используется при сборке и не включена как база в пользовательский HTML. При её перепубликации следует сохранять атрибуцию, ссылку на лицензию и обозначать изменения. Обычное использование инструмента не означает, что код Plyra нужно лицензировать как CC BY. [Лицензия caniuse-lite](https://github.com/browserslist/caniuse-lite/blob/main/LICENSE).

Pillow и шрифты используются для создания учебных иллюстраций, а не поставляются пользователю как исполняемые библиотеки или шрифтовые файлы. Созданные изображения не становятся автоматически MPL или Apache из-за лицензий инструментов. Если позже включать сами шрифты или генератор с зависимостями в отдельный дистрибутив, сохранить соответствующие условия. [Pillow](https://pillow.readthedocs.io/en/stable/about.html), [DejaVu](https://dejavu-fonts.github.io/License.html).

## Что потребуется для перехода

1. Установить фактического владельца прав на исходный код. В пользовательском ZIP не было `LICENSE`, `NOTICE` или `COPYING`. Нынешняя строка `Atlas contributors` — оформление подготовленного комплекта, не подтверждение владения правами. Если исходники ваши, вы можете выбрать лицензию для своего кода; для чужого кода нужны соответствующие права и сохранение его условий.
2. Заменить корневой `LICENSE` полным текстом Apache-2.0, согласованно обновить `package.json`, корень `package-lock.json` и описание лицензии в README. Оставить настоящие copyright исходных правообладателей. Для новых исходных файлов можно использовать `SPDX-License-Identifier: Apache-2.0`.
3. Сохранить сведения о происхождении и сторонних компонентах в NOTICE/THIRD_PARTY_NOTICES. По Apache нужно передавать лицензию, сохранять применимые уведомления и помечать изменённые файлы; если есть соответствующий исходный NOTICE, сохранить его сведения. Наличие файла NOTICE само по себе не заменяет эти требования.
4. Пересобрать автономный HTML: он содержит текст основной лицензии и сторонние уведомления. Проверить, что README, исходники и скачиваемый файл описывают одну лицензионную схему.
5. Отдельно определить условия для статей и внешних активов. Сейчас рабочие статьи исключены из лицензии программного обеспечения, их права зарезервированы. Статьи Харела и Александера только цитируются ссылками; неизвестное по правам фото `boiler.jpg` исключено из выпуска. Нельзя объявлять весь этот материал своим кодом Apache.

Ранее выданные права по MIT не отзываются одним переименованием лицензии в новой версии. Все перечисленные шаги перехода — предложение; текущий `LICENSE` остался MIT.
